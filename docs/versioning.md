# 版本管理

[返回项目说明](../README.md)

## 当前阶段

当前版本是 **0.1.0 测试版**。包版本保持 `0.1.0`，Git 标签为 `v0.1.0`，GitHub Release 标记为 **Pre-release**；“测试版”是发布状态，不是额外的包版本后缀。项目名保持 `video-remake`。

## 版本约定

- `0.1.x`：当前功能的小改进与问题修复。
- `0.2.0` 等次版本：新增较大功能，或调整接口、配置、模板格式；涉及迁移时在更新记录中说明。
- `1.0.0`：核心流程与兼容约定稳定后再发布，不预设日期。
- `main` 是开发分支；需要固定发布版本时使用对应标签。已发布的标签不移动、不覆盖，修复发布为新版本。

所有 `0.x` 版本默认作为预发布。项目版本、制作中的模板版本（v1、v2）和 HyperFrames 依赖版本分别管理，不随项目版本机械同步递增。

## 发布步骤

1. 将 `CHANGELOG.md` 的“未发布”内容整理为新版本，填写发布日期、变化、限制与迁移事项。
2. 更新 `package.json` 的版本、`package-lock.json` 顶层与根包版本，以及 README 的版本标记和发布链接、本页的当前版本说明。可用 `npm version <版本> --no-git-tag-version` 同步包版本，再更新文档。
3. 执行 `npm test` 和 `git diff --check`。记录通过、失败和跳过数量；失败时先修复并重新验证，全部检查通过后才能提交、推送和发布。
4. 提交并推送发布内容，在该提交上建立带说明的 `v<版本>` 标签并推送。
5. 创建同名 GitHub Release，测试版本勾选 Pre-release，说明本次功能、已知限制与验证结果。

只发布仓库源码与通用文档，不上传本地制作、原片、账号配置或密钥。当前 npm 包为 `private: true`，不发布到 npm。
